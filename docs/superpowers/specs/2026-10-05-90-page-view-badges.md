# Spec — widok Strony z badge'ami Wzmianek (#90)

> Data: 2026-10-05 · Issue: #90 · Milestone: M1 · Decyzje: ADR-004, ADR-005 · Bazuje na: #89 (`routes/$.tsx`, `wiki.ts`) · Makiety: `docs/mockups/book.html`, `character.html`, `universe.html` · Pojęcia: `CONTEXT.md` (Wzmianka, Odnośnik, Źródło, Weryfikacja)

## Cel

Strona wygląda jak na makietach. U góry nagłówek z frontmattera, pod nim treść Markdown, na dole stopka ze Źródłami i Weryfikacją. Każdy Odnośnik do Postaci lub Miejsca jest badge'em, który prowadzi do tej Strony. Odnośnik do nieistniejącej Strony to zwykły tekst.

## Decyzje

| Temat | Decyzja | Powód |
|---|---|---|
| Render Markdown | `react-markdown` z własnym rendererem `a` | issue tego wymaga, a cała logika linków siedzi w jednym komponencie. Plugin remark dałby ten sam efekt przy większej ilości kodu |
| Gdzie badge | każdy Odnośnik do `/characters/` lub `/places/` w dowolnym miejscu treści | jedna reguła oparta na prefiksie Ścieżki, bez parsowania sekcji `## Postacie` / `## Miejsca`. Działa też w `## Powiązania` |
| Wygląd Wzmianki | badge inline, a po nim opis po myślniku, tak jak w Markdownie | bez kart z makiety; opis to zwykły tekst elementu listy |
| Istnienie Strony | `Set` Ścieżek z `usePages()` | lista jest już w cache po panelu bocznym, więc nie ma zapytania na każdy link |
| Zepsuty Odnośnik | `<span>` z tekstem linku | OKF dopuszcza zepsute linki |
| Odnośnik wewnętrzny | `href` zaczyna się od `/` | fixture'y używają ścieżek absolutnych; ścieżki względne dojdą, gdy pojawią się w treści |
| Odnośnik zewnętrzny | `<a target="_blank" rel="noopener noreferrer">` | wychodzi poza SPA |
| `status` | pill w nagłówku, tylko gdy pole jest we frontmatterze | decyzja usera: ukryj, gdy brak |
| Źródła i Weryfikacja | w stopce, nie w nagłówku | tak jest w makiecie `book.html`; issue wymienia je w „header”, ale o układzie decyduje makieta |
| Parsowanie frontmattera | `parsePage` w `wiki.ts`, a `store.ts` go importuje | dziś `parseFrontmatter` siedzi w store; parsowanie ma być w jednym miejscu |
| Kolory badge'y | tokeny `--character` / `--place` w `:root` w `index.css` | hexy z makiety; dark mode nadal poza zakresem |
| Ikony | 2 inline SVG z makiety (osoba, pinezka) | `lucide-react` nie jest zainstalowany; nowa zależność dla 2 ikon jest zbędna |
| Typografia treści | mały blok CSS `.page-body` (h2, p, ul, a) w `index.css` | `@tailwindcss/typography` nie jest zainstalowany, a potrzebujemy 4 elementów |

## Tokeny (`src/index.css`)

| Zmienna | Wartość | Rola |
|---|---|---|
| `--character` / `--character-foreground` | `#F8E9DF` / `#6B2C12` | badge Postaci (terakota) |
| `--place` / `--place-foreground` | `#E4EDF7` / `#1F4A7A` | badge Miejsca (niebieski) |

Zmienne są rejestrowane w `@theme inline` jako `--color-*`, tak jak pozostałe tokeny.

## Logika (`src/wiki.ts`)

```ts
interface Frontmatter {
  type: PageType
  title?: string
  description?: string
  author?: string
  status?: string
  book?: string
  universe?: string
  sources?: { id: string; resource?: string; title?: string }[]
  generated?: { by: string; at: string }
  verified?: { by: string; at: string }[]
}

parsePage(content: string): { frontmatter: Frontmatter; body: string }
```

- Rzuca `Error('Missing frontmatter')`, gdy nie ma bloku `---` (tak jak dziś w store).
- `body` to treść po zamykającym `---`, bez wiodących pustych linii.

## Komponenty (`src/components/PageView.tsx`)

**`PageView({ page })`** parsuje `page.content` przez `parsePage`:

1. **Nagłówek:** Ścieżka (mono, muted), `<h1>` z tytułem (Newsreader), pod nim wiersz z Typem strony i pillem `status`, jeśli jest. Pod spodem `author` (dla książki) i `description`, jeśli są.
2. **Treść:** `<div className="page-body"><ReactMarkdown components={{ a: WikiLink }}>{body}</ReactMarkdown></div>`.
3. **Stopka** (border-top, muted, 13px), renderowana tylko gdy jest co pokazać:
   - `Sources:` i lista tytułów (`title ?? id`), każdy jako link zewnętrzny, gdy ma `resource`;
   - `Generated by <generated.by>`, gdy jest;
   - `verified by <by>, …`, gdy `verified` jest niepuste.

**`WikiLink({ href, children })`** ma `usePages()` → `Set` Ścieżek:

| `href` | Render |
|---|---|
| zaczyna się od `/characters/`, Strona istnieje | `<Link>` w badge'u `bg-character text-character-foreground` z ikoną osoby |
| zaczyna się od `/places/`, Strona istnieje | `<Link>` w badge'u `bg-place text-place-foreground` z ikoną pinezki |
| inny wewnętrzny (`/…`), Strona istnieje | zwykły `<Link>` (kolor primary) |
| wewnętrzny, Strony brak | `<span>` z `children` |
| zewnętrzny | `<a target="_blank" rel="noopener noreferrer">` |

`<Link to="/$" params={{ _splat: pageSplat(href) }}>`, tak jak w panelu bocznym. Dopóki `usePages()` się ładuje, Odnośniki wewnętrzne renderują się jako tekst. W fake store dane są synchroniczne, więc nie widać mignięcia.

**`routes/$.tsx`**: ładowanie i „Page not found.” bez zmian. Zamiast stubu tytułu jest `<PageView page={page} />`, a dla `universe` pod nim `UniverseMembers`.

## Testy

1. `wiki.test.ts`: `parsePage` na fixture „Ostatnie życzenie” zwraca `frontmatter.type === 'book'`, a `body` zaczyna się od `## Streszczenie`. Treść bez frontmattera rzuca błąd.
2. `app.test.tsx`:
   - Strony `book`, `character`, `place` i `universe` renderują `<h1>` z tytułem i przynajmniej jeden nagłówek treści;
   - `/books/ostatnie-zyczenie`: Geralt, Jaskier, Yennefer, Renfri i Blaviken to linki; klik w „Renfri” zmienia URL na `/characters/renfri--ostatnie-zyczenie`;
   - `/books/ostatnie-zyczenie`: „Nenneke” to tekst, nie link (`queryByRole('link', { name: 'Nenneke' })` jest `null`);
   - `status`: pill jest na `snaut--solaris`, a na „Ostatnim życzeniu” go nie ma;
   - stopka „Ostatniego życzenia” pokazuje źródło „Ostatnie życzenie — Wikipedia” i `human:stokuj`.
