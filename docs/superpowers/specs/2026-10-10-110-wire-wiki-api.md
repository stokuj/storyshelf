# Spec — Ekrany Wiki na prawdziwym API Stron (#110)

> Data: 2026-10-10 · Issue: #110 · Milestone: M2 · Zależy od: #108 (API Stron), #109 (klient `api()`) · Backend: `backend-django/wiki/views.py`, `serializers.py`, `config/pagination.py` · Follow-upy z #107 przeniesione do #110

## Cel

Sidebar, widok Strony, Edycja i Historia czytają i zapisują dane w bazie przez API z #108. Błędy z prawdziwego backendu (400, 404, 409, 5xx) mają czytelne stany w UI. To, co nie ma jeszcze backendu (Agent, Propozycje, Profil), zostaje na małym fake'u albo jest ukryte.

## Warstwa API (`frontend/src/api/`)

- `wiki.ts` (nowy): `listPages(type?)`, `getPage(path)`, `listVersions(path)`, `savePage(path, content, baseVersion)`, `createBook(candidate)`. Ścieżka w URL bez wiodącego `/`: `/wiki/pages/books/solaris.md`.
- `hooks.ts`: te same nazwy i sygnatury hooków (`usePages`, `usePage`, `useVersions`, `useSavePage`, `useCreateBook`), nowe `queryFn`/`mutationFn`. `useSavePage(path)` przyjmuje `{ content, baseVersion }`. Klucze zapytań bez zmian.
- `store.ts`: zostają `searchCandidates` (bez dopasowania zwraca pierwszych 3 Kandydatów; filtr „nie ma jeszcze w Wiki” usunięty, bo fake nie zna Stron — `CandidateCard` i tak pokazuje „Already in Wiki”), `getProfile`, `setProfilePublic`, `listProposals`/`getProposal`/`accept`/`reject` (ukryte). Usunięte: `pages`, `versions`, `writePage`, `savePage`, `createBook`, `generatePage`, `withStatus`, glob `.md`.

## Testy (Vitest, mock `fetch`)

- Helper `src/test/mockWikiApi.ts` na bazie `mockFetch.ts`: obsługuje `GET/POST /api/wiki/pages/`, `GET/PUT .../{path}`, `GET .../versions/`, z danymi z backendowych fixtures; pozwala wymusić status (400/404/409/500) dla danego żądania.
- Przypadki: sidebar, widok i Historia na danych z API; zapis wysyła `base_version` i odświeża Historię; 400 → komunikat backendu w edytorze; 409 → komunikat i Reload; 404 vs 500 w widoku Strony; błąd listy → alert w sidebarze; brak linków do Propozycji i Generowania; „Yes, add” → `POST` i nawigacja; `pagePath` normalizacja (unit).
- `proposal.test.tsx` renderuje `ProposalView` bezpośrednio.
